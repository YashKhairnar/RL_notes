Reinforcement Learning · Chapter 13

Policy Gradient Methods

A step-by-step path from representing a policy to learning it directly with REINFORCE.

Start here

The big picture

Most earlier control methods learn action values first. For example, Q-learning estimates q(s,a) and then chooses the action with the largest value.

Policy gradient methods take a different route: they represent the policy directly and adjust it so that actions followed by better outcomes become more likely.

Value-based control

Learn values → choose actions from those values.

Policy-based control

Represent the policy → improve its parameters directly.

Core question: how should we change the policy’s parameters so that the agent receives higher expected return?

Step 1

Representing the policy

Let the policy be represented by parameters θ. Given a state, the policy produces a probability for each action:

πθ(a | s) = probability of choosing action a in state s

For discrete actions, a neural network can output one preference, or logit, for each action. Softmax converts these preferences into probabilities:

πθ(a | s) = exp(hθ(s,a)) / Σb exp(hθ(s,b))

For example, the policy might output 0.70 for left, 0.20 for straight, and 0.10 for right. The agent samples an action from this distribution.

This makes exploration part of the learned policy. The policy can gradually approach deterministic behavior, but it can also remain stochastic when randomness is useful.

A probability is not a value estimate. It answers “how likely is this action?”; a Q-value answers “how good is this action expected to be?”

Step 2

Defining performance: J(θ)

Before improving the policy, we need to define what “better” means. We measure the expected return produced by the current policy.

For an episodic task that starts at s0:

J(θ) = vπθ(s0)

Equivalently, if τ denotes a complete trajectory:

J(θ) = Eτ ∼ πθ[R(τ)]

The policy and environment may be stochastic, so different episodes can have different returns. J(θ) averages over those possibilities.

Step 3

Improving the policy

We want to change θ in the direction that increases J(θ). The gradient tells us how performance changes when each parameter changes:

∇θJ(θ) = direction in parameter space that increases expected return

Therefore, we use gradient ascent:

θ ← θ + α ∇θJ(θ)

Here α is the learning rate. The challenge is that we do not know the exact gradient. The policy gradient theorem tells us what that gradient looks like in terms of states, actions, and returns.

Step 4 · Section 13.2

The policy gradient theorem

Let μπ(s) describe how often the current policy visits state s. Let qπ(s,a) be the expected return after taking action a in state s and then following the policy.

The theorem states:

∇θJ(θ) ∝ Σs μπ(s) Σa qπ(s,a) ∇θπ(a | s,θ)

μπ(s)

States visited more often have more influence on learning.

qπ(s,a)

Good actions receive more influence than poor actions.

∇π(a|s,θ)

Shows how parameter changes alter the action probability.

∝

Means proportional to; the constant can be absorbed into α.

In words: combine how often a state is visited, how good an action is, and how the policy probability changes.

Why does the theorem matter?

Changing θ changes both the actions selected and the future states visited. The theorem handles this dependency without requiring us to differentiate through the environment’s transition dynamics.

Step 5

Making the theorem sampleable

The theorem contains a sum over every possible action. We can rewrite it using:

∇θπθ(a|s) = πθ(a|s) ∇θ log πθ(a|s)

This is the log-derivative trick. It lets us express the action sum as an expectation over an action sampled from the policy:

∇θJ(θ) ∝ Eπ[qπ(St,At) ∇θlog πθ(At|St)]

Now the procedure is practical: visit a state, sample an action, measure how good the result was, and use that sample to estimate the gradient.

Step 6 · Section 13.3

REINFORCE

We still do not know qπ(St,At). REINFORCE estimates it with the observed Monte Carlo return:

Gt = Rt+1 + γRt+2 + γ2Rt+3 + ···

After an episode finishes, Gt is available for every action that was taken. The update becomes:

θ ← θ + α Gt ∇θ log πθ(At|St)

Gt

Measures the outcome that followed the selected action and controls update strength.

∇ log π

Points toward parameter changes that increase the probability of the selected action.

Algorithm

  1. Initialize θ.
  2. Generate a complete episode using πθ.
  3. For every time step t, calculate Gt.
  4. Update θ using Gt∇ log πθ(At|St).
  5. Repeat with the updated policy.

REINFORCE is called Monte Carlo because it waits until the episode ends and uses the complete return. It does not bootstrap from an estimated value of a future state.

Strength and limitation

Strength: it uses an unbiased estimate of the policy gradient and does not need an environment model.

Limitation: complete returns can vary greatly, producing high variance and slow learning. The next improvement is to use a baseline to reduce this variance.

Final takeaway: complete an episode, see which selected actions were followed by good returns, and increase the probability of those actions.

Reference: Sutton & Barto Chapter 13.2–13.3 summary.

Step 7 · Section 13.4

REINFORCE with baseline

REINFORCE has the correct average direction, but its updates can be very noisy. The return from one episode may be high simply because the episode was lucky, or low because the environment was unlucky.

To make the update more stable, we compare the return with a baseline:

θ ← θ + α [Gt − b(St)] ∇θ log πθ(At | St)

The quantity being used to update the policy is now:

Gt − b(St)

This tells us whether the action performed better or worse than expected in that state.

Why does subtracting a baseline help?

Suppose the agent receives a return of 10. That sounds good, but it means different things in different states:

State A

Typical return is 2. A return of 10 is excellent, so strongly reinforce the action.

State B

Typical return is 20. A return of 10 is poor, so reduce the action’s probability.

The raw return does not provide this context. The baseline gives us a reference point.

The baseline does not change the expected gradient

The baseline may reduce variance as long as it depends on the state but does not depend on the selected action. Its expected contribution is zero:

Σa b(s) ∇θπ(a | s, θ)
= b(s) ∇θΣaπ(a | s, θ)
= b(s) ∇θ1 = 0

Therefore, subtracting the baseline changes the individual samples but not the expected policy gradient.

The natural baseline: the state-value function

A useful choice is an estimate of the state value:

b(St) = Vπ(St)

The state value represents the average return expected from the state, regardless of which particular action is selected. With this choice, the update signal becomes the advantage:

Aπ(s,a) = Qπ(s,a) − Vπ(s)

In practice, REINFORCE uses an estimate:

Ât = Gt − V̂(St, w)

Interpretation:

Positive advantage → the action was better than expected → increase its probability.

Negative advantage → the action was worse than expected → decrease its probability.

What changes in the algorithm?

  1. Generate a complete episode.
  2. Calculate the return Gt for each time step.
  3. Estimate the baseline V̂(St, w).
  4. Calculate Ât = Gt − V̂(St, w).
  5. Update the policy using Ât∇ log πθ(At|St).
  6. Update the value-function estimate toward Gt.

There are now two learned components:

Actor

The policy πθ, which chooses actions and is updated using the advantage.

Baseline / value estimator

The value estimate V̂(s,w), which predicts expected returns and reduces update variance.

Important distinction

At this stage, the value estimate is used as a baseline for the policy update. REINFORCE still uses the complete Monte Carlo return, so it does not bootstrap from a later estimated value. Actor–critic methods will later use bootstrapping directly in the critic.

Main takeaway: REINFORCE asks “how large was the return?” REINFORCE with baseline asks “was the return better or worse than what is normal for this state?”

Reference: Sutton & Barto Chapter 13.4 summary.

Step 8 · Section 13.5

Actor–critic methods

REINFORCE with baseline already contains two useful components: a policy and a value estimate. Actor–critic methods give these two components separate learning roles and update them together.

The actor

The policy πθ. It chooses actions and changes its probabilities.

The critic

The value function V̂(s,w). It evaluates states and provides a learning signal for the actor.

What changes from REINFORCE?

REINFORCE waits until the episode ends to calculate the complete return Gt. The critic can instead make an immediate prediction about the next state.

The one-step TD target is:

Rt+1 + γV̂(St+1,w)

Comparing this target with the critic’s current prediction gives the TD error:

δt = Rt+1 + γV̂(St+1,w) − V̂(St,w)

For a terminal next state, we use V̂(St+1,w)=0.

The critic update

The critic learns by reducing the difference between its current estimate and the TD target:

w ← w + αwδt∇wV̂(St,w)

If δt is positive, the outcome was better than expected, so the critic raises its estimate of the current state. If it is negative, the critic lowers it.

The actor update

The actor uses the same TD error as an estimate of the action’s advantage:

θ ← θ + αθδt∇θlog πθ(At|St)

The sign of δt determines what happens:

δt > 0

The transition was better than expected. Increase the probability of the selected action.

δt < 0

The transition was worse than expected. Decrease the probability of the selected action.

One-step actor–critic algorithm

  1. Observe state St.
  2. Sample action At from πθ.
  3. Take the action and observe Rt+1 and St+1.
  4. Calculate δt = Rt+1 + γV̂(St+1,w) − V̂(St,w).
  5. Update the critic using δt.
  6. Update the actor using δt∇ log πθ(At|St).
  7. Continue with the next state.

Simple interpretation: the critic says, “that outcome was better or worse than I expected.” The actor uses that feedback to decide whether the selected action should become more or less likely.

Why use actor–critic methods?

They are online and incremental: the agent can learn after every step instead of waiting for a complete episode. Bootstrapping also usually reduces variance and makes learning faster.

The trade-off is that the TD estimate can be biased if the critic is inaccurate. In practice, this bias is often worthwhile because the reduction in variance is substantial.

How does this connect to REINFORCE with baseline?

REINFORCE with baseline uses Gt − V̂(St,w), which is a Monte Carlo advantage estimate. Actor–critic replaces the full return with the one-step TD error δt. Both use the value function to give the actor a better learning signal, but actor–critic bootstraps.

Reference: Sutton & Barto Chapter 13.5 summary.

Step 9 · Section 13.6

Policy gradients for continuing problems

So far, we have discussed episodic tasks: an episode begins, eventually ends, and the return can be calculated from that ending point. Some environments do not have natural terminal states, such as a robot operating continuously or a server handling requests.

For these tasks, we cannot define performance as the return from one starting state. Instead, we commonly maximize the average reward per time step:

J(θ) = r(πθ) = limh→∞ (1/h) Σt=1h E[Rt | πθ]

In simple words, the objective asks:

How much reward does this policy earn on average while running forever?

The steady-state distribution

In an episodic problem, μπ(s) described how often states are visited during an episode. In a continuing problem, it represents the long-run or steady-state distribution of states under the policy.

Under the usual ergodicity assumption, the long-run average reward can be written as:

r(π) = Σs μπ(s) Σa π(a|s) Σs′,r p(s′,r|s,a)r

This averages the immediate reward over:

  1. How often the policy reaches state s.
  2. Which action the policy chooses in s.
  3. What next state and reward the environment produces.

Differential returns

For continuing tasks, the ordinary discounted return is not always the most natural signal. We subtract the policy’s average reward from each reward and use the resulting differential return:

Gt = (Rt+1 − r(π)) + (Rt+2 − r(π)) + ···

A reward above the long-run average is positive news; a reward below the average is negative news. The policy-gradient theorem keeps the same overall structure, but the state distribution and return are now defined for the continuing setting.

How does actor–critic change?

The actor still uses a score-function update, and the critic still estimates values. The difference is that the critic learns differential values relative to the average reward rather than values measured from an episode start.

Step 10 · Section 13.7

Policy parametrization for continuous actions

For a discrete action space, a policy can output one probability for each action. A continuous action space has infinitely many possible actions, so we cannot list a separate probability for every one.

Instead, the policy describes a continuous probability distribution. The neural network learns the distribution’s parameters, such as its mean and standard deviation.

Gaussian policy

For a scalar action, a common choice is a normal distribution:

π(a|s,θ) = [1/(σ(s,θ)√(2π))] exp(−(a−μ(s,θ))²/[2σ(s,θ)²])

The policy network receives state s and produces:

μ(s,θ)

The mean action. It controls the center of the distribution and usually represents the policy’s preferred action.

σ(s,θ)

The standard deviation. It controls how much randomness or exploration is used.

The agent samples a real-valued action from this distribution. During learning, the policy can change both the action it prefers and the amount of exploration it uses.

Keeping the standard deviation positive

A standard deviation must be positive. A common parameterization lets the network output an unrestricted number and exponentiates it:

μ(s,θ) = θμTxμ(s)
σ(s,θ) = exp(θσTxσ(s))

The exponential guarantees σ > 0. In modern implementations, networks often output log σ or log σ² for the same reason.

Does the policy-gradient idea change?

No. The action is now sampled from a probability density rather than a discrete probability table, but the update still has the same structure:

θ ← θ + α × learning signal × ∇θlog πθ(At|St)

For actor–critic methods, the learning signal can still be the TD error δt. The only change is how log π is calculated for the chosen continuous action.

Key idea: in discrete actions, the policy learns probabilities for named actions. In continuous actions, it learns the parameters of a distribution from which actions are sampled.

Example · steering a vehicle

The policy might output μ = 0.2 and σ = 0.1 for a steering action. Most sampled steering values will be close to 0.2, but some variation remains. If steering values near 0.2 produce positive TD errors, the policy shifts its distribution toward them. If they perform poorly, the distribution shifts away.
