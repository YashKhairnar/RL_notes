Dynamic Programming: Complete Chapter 4

Intuition-first study guide for Sections 4.1–4.8 of Reinforcement Learning: An Introduction (2nd edition) by Richard S. Sutton and Andrew G. Barto—explaining how Bellman equations become working algorithms.

Turn Bellman equations into update rules—assuming you know the model.

In Chapter 3, the Bellman equations were consistency checks: they told us what a true value function must satisfy, but not how to compute it. Chapter 4 shows that if you know the environment's dynamics p(s', r | s, a), you can turn those equations into iterative assignment rules. Starting from arbitrary guesses, you repeatedly replace each state's value with its one-step expected lookahead until the numbers stop moving.

4.1 Policy evaluation (prediction)

Goal: Given an arbitrary policy π, compute its state-value function vπ(s) for every state s ∈ 𝒮.

Because this requires the dynamics function p(s', r | s, a), we must know the full MDP model. To compute vπ iteratively, pick any arbitrary initial values v0 (with v0(terminal) = 0), and generate successive approximations v1, v2, v3, ... by turning the Bellman equation for vπ directly into an update rule:

vk+1(s) ≐ Σa π(a | s) Σs', r p(s', r | s, a) [ r + γ vk(s') ] Eq. (4.5) · Here k denotes the iteration number; vk = vπ is a fixed point of this update rule

How each iteration actually works

  1. One operation across every state: To produce the next approximation vk+1 from vk, apply Eq. (4.5) to every state s ∈ 𝒮. You replace the old value of s with a new value computed from: (a) the expected immediate rewards, and (b) the old values vk(s') of s's successor states, weighted by the one-step transition probabilities under π.
  2. Why it converges: vk = vπ is a fixed point (if you plug in vπ, you get vπ back). As k → ∞, the sequence {vk} is guaranteed to converge to vπ whenever γ < 1 or all episodes terminate.
  3. Two-array vs. in-place implementation: A literal implementation of Eq. (4.5) stores two separate arrays—one for vk and one for vk+1—so updates never mix old and new values during a sweep. In practice, we usually update in-place using a single array V(s), overwriting each state immediately; this uses half the memory and typically converges faster because later states in the sweep use fresher estimates.

Key terms: This is an expected update (because it averages over all possible next states using p, rather than sampling one outcome) and it uses bootstrapping (updating an estimate V(s) based on other estimates V(s')).

Algorithm: Iterative Policy Evaluation (in-place)
Input: policy π, accuracy threshold θ > 0
Initialize V(s) arbitrarily for all s ∈ 𝒮, except V(terminal) = 0

Loop:
    Δ ← 0
    For each s ∈ 𝒮:
        v ← V(s)
        V(s) ← Σa π(a | s) Σs', r p(s', r | s, a) [ r + γ V(s') ]
        Δ ← max(Δ, |v − V(s)|)
Until Δ < θ

4.2 Policy improvement

The core intuition: Once we know vπ(s), we can ask: "At state s, what if I disobey π just once, take action a instead, and then go back to following π?" That one-step deviation has value qπ(s, a) = Σs', r p(s', r | s, a)[r + γ vπ(s')]. If qπ(s, a) > vπ(s), then switching to a at state s every time is guaranteed to be even better—even if we switch actions across all states at once.

Why simultaneous changes don't break things: Policy Improvement Theorem

It isn't immediately obvious that changing π at every state simultaneously won't cause different states to interfere with each other. The Policy Improvement Theorem proves that if π' looks at least as good as π for a one-step deviation in every state, then π' is genuinely at least as good as π forever:

If   qπ(s, π'(s)) ≥ vπ(s)   for all s ∈ 𝒮,   then   vπ'(s) ≥ vπ(s)   for all s ∈ 𝒮. Eqs. (4.7)–(4.8) · If strict inequality holds at even one state, then vπ'(s) > vπ(s) at that state
vπ(s) ≤ qπ(s, π'(s))
1. Start from the theorem's assumption (4.7) at state s
      = 𝔼[Rt+1 + γ vπ(St+1) | St = s, At = π'(s)]
2. Expand qπ: take π'(s) now, then follow π from St+1 onward
      = 𝔼π'[Rt+1 + γ vπ(St+1) | St = s]
3. Rewrite the conditioning as following π' on step t
      ≤ 𝔼π'[Rt+1 + γ qπ(St+1, π'(St+1)) | St = s]
4. Key move: apply assumption (4.7) again at the next state St+1, replacing vπ(St+1) with ≤ qπ(St+1, π'(St+1))
      = 𝔼π'[Rt+1 + γ Rt+2 + γ2 vπ(St+2) | St = s]
5. Expand qπ one step further—now two steps follow π'
      ≤ ··· ≤ 𝔼π'[Rt+1 + γ Rt+2 + γ2 Rt+3 + ··· | St = s] = vπ'(s)
6. Repeat inductively forever: the remaining γk vπ(St+k) vanishes, leaving the true return under π'

Greedy policy improvement & how we know we've reached optimality

To construct an improved policy π' across all states at once, simply pick the action with the highest one-step lookahead in every state:

π'(s) ≐ arg maxa qπ(s, a) = arg maxa Σs', r p(s', r | s, a) [ r + γ vπ(s') ] Eq. (4.9) · Because the maximum over all actions is always ≥ what π chose, Eq. (4.7) holds automatically

Stopping condition = Optimality: What happens if π' gives the exact same values as π (vπ' = vπ)? Then for every s, vπ'(s) = maxa Σs', r p(s', r | s, a)[r + γ vπ'(s')]—which is the Bellman optimality equation (3.19)! So the moment greedy improvement stops changing the value function, both π and π' are guaranteed to be optimal (vπ' = v*).

4.3 Policy iteration

The core intuition: Evaluation tells you how good your current policy is; Improvement uses those numbers to build a strictly better policy. Policy Iteration simply chains these two steps in a loop until the policy stops changing.

Algorithm: Policy Iteration
1. Initialization:
   V(s) ∈ ℝ and π(s) ∈ 𝒜(s) arbitrarily for all s ∈ 𝒮

2. Policy Evaluation:
   Run Iterative Policy Evaluation until Δ < θ (warm-started from previous V!)

3. Policy Improvement:
   policy-stable ← true
   For each s ∈ 𝒮:
       old-action ← π(s)
       π(s) ← arg maxa Σs', r p(s', r | s, a) [ r + γ V(s') ]
       If old-action ≠ π(s), then policy-stable ← false
   If policy-stable, then stop and return V ≈ v* and π ≈ &pi>*; else go to 2

4.4 Value iteration

Why Policy Iteration feels wasteful: On every iteration, you wait for Policy Evaluation to converge to high precision over many full sweeps—only to throw away the old policy and change it anyway! In practice, the greedy arg max policy often stops changing after just 2 or 3 sweeps of evaluation.

The Value Iteration shortcut: Truncate Policy Evaluation to a single sweep, and fold the greedy max directly into the update. Instead of evaluating a fixed policy π and then improving it, every sweep updates V(s) assuming you will take the best action right now:

vk+1(s) ≐ maxa Σs', r p(s', r | s, a) [ r + γ vk(s') ] Eq. (4.10) · Literally the Bellman optimality equation (3.19) turned into an assignment rule; converges to v*

Notice that Value Iteration doesn't even maintain an explicit policy π in memory during the loop—it only extracts π once at the very end via one greedy lookahead pass.

Algorithm: Value Iteration (in-place)
Input: accuracy threshold θ > 0
Initialize V(s) arbitrarily for all s ∈ 𝒮, except V(terminal) = 0

Loop:
    Δ ← 0
    For each s ∈ 𝒮:
        v ← V(s)
        V(s) ← maxa Σs', r p(s', r | s, a) [ r + γ V(s') ]
        Δ ← max(Δ, |v − V(s)|)
Until Δ < θ

Output deterministic policy π such that:
    π(s) = arg maxa Σs', r p(s', r | s, a) [ r + γ V(s') ]

4.5 Asynchronous dynamic programming

The core intuition: Think of a massive maze where the exit is in one corner. A synchronous sweep updates every single dead-end room on every pass, even when none of their neighbors have changed. Asynchronous DP drops the full-sweep requirement: you can update states in any order, backing up important states dozens of times before touching irrelevant ones once.

  • When it converges: As long as every state continues to be updated eventually (none are permanently ignored), asynchronous DP still converges to v*.
  • Real-time DP: Because you don't have to sweep all of 𝒮, you can run DP updates while an agent is actually acting—updating only the states along the agent's trajectory and focusing compute where it matters most.

4.6 Generalized Policy Iteration (GPI)

The unifying lens of RL: Policy Iteration waits for full evaluation before 1 improvement step. Value Iteration does 1 evaluation sweep per improvement. Asynchronous DP updates single states in any order. Generalized Policy Iteration (GPI) is the general name for any algorithm that lets an evaluation process (V → vπ) and an improvement process (π → greedy(V)) interact, regardless of granularity.

The tug-of-war explained: Evaluation and improvement compete because making π greedy for V changes π, which immediately makes V inaccurate for the new policy (pulling it off the blue line); evaluating the new π changes V, which can make π non-greedy (pulling it off the green line). Yet they cooperate overall, zigzagging toward the unique intersection (v*, π*).

4.7 Efficiency of dynamic programming

Why DP is actually fast—and where it hits a wall: Suppose an MDP has n = 100 states and k = 2 actions. Checking every deterministic policy by brute force means testing 2100 ≈ 1030 policies—completely impossible. DP finds an optimal policy in time polynomial in n and k (and is much faster in practice than linear programming).

The catch (Curse of Dimensionality): The number of states n = |𝒮| itself grows exponentially with the number of state variables (e.g., 10 variables with 10 values each gives 1010 states). That explosion is a property of the problem, not a flaw of DP—and it is why Chapters 5–13 replace full-sweep tables with sampling and function approximation.

4.8 Summary

Dynamic Programming solves finite MDPs when p(s', r | s, a) is known by turning Bellman equations into expected, bootstrapping updates.

Problem Bellman Equation Used DP Algorithm
Prediction (evaluate π) Bellman Expectation Equation for vπ — Eq. (4.5) Iterative Policy Evaluation
Control (find π*) Bellman Expectation + Greedy Improvement — Eqs. (4.5) & (4.9) Policy Iteration
Control (find π*) Bellman Optimality Equation for v* — Eq. (4.10) Value Iteration

Expected Updates

DP computes exact expectations over all possible next states and rewards using p(s', r | s, a), rather than sampling experience.

Bootstrapping

DP updates state-value estimates using other state-value estimates—a core idea that carries into TD learning (Chapter 6).

GPI Blueprint

Interleaving evaluation and improvement at any granularity (from full sweeps to 1-step asynchronous updates) powers nearly all RL algorithms.
