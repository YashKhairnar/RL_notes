Monte Carlo Methods: Complete Chapter 5

Self-contained study guide for Sections 5.1–5.8 of Reinforcement Learning: An Introduction (2nd edition) by Richard S. Sutton and Andrew G. Barto—learning directly from sampled episodes without knowing the environment's dynamics.

No model needed: just average the actual returns you observe.

Dynamic Programming (Chapter 4) required the full transition probabilities p(s', r | s, a). Monte Carlo (MC) methods drop that requirement completely: they learn value functions and optimal policies directly from experience—complete episodes of states, actions, and rewards. Instead of bootstrapping from other estimates, MC simply averages the actual discounted returns Gt observed after visiting each state or state–action pair.

5.1 Monte Carlo prediction

Goal: Estimate vπ(s) for a given policy π using only sample episodes generated by following π (requiring episodic tasks so every episode eventually terminates and yields a complete return Gt).

Since vπ(s) is the expected return starting from s, the most direct way to estimate it without a model is to average the actual returns observed after visits to s:

  • First-visit MC: In each episode, average the return following only the first time state s is visited. Because each episode's first-visit return is an independent, identically distributed (i.i.d.) sample of vπ(s), the sample average converges to vπ(s) by the Law of Large Numbers (with standard error shrinking as 1/√n).
  • Every-visit MC: Average the returns following every visit to s, even multiple times within the same episode. Returns within one episode are correlated, yet every-visit MC still converges to vπ(s).
Algorithm: First-Visit MC Prediction (for estimating V ≈ vπ)
Input: a policy π to be evaluated
Initialize V(s) ∈ ℝ arbitrarily, and Returns(s) ← empty list, for all s ∈ 𝒮

Loop forever (for each episode):
    Generate an episode following π: S0, A0, R1, S1, A1, R2, ..., ST−1, AT−1, RT
    G ← 0
    For each step of episode, t = T−1, T−2, ..., 0:
        G ← γ G + Rt+1
        Unless St appears in S0, S1, ..., St−1:
            Append G to Returns(St)
            V(St) ← average(Returns(St))

How the First-Visit MC algorithm works (line by line)

  1. Generate one complete episode: Run policy π from start to termination, recording the sequence of states, actions, and rewards. We cannot update anything yet because MC needs the full return Gt.
  2. Walk backward from t = T−1 down to 0: Why backward? Because Gt = Rt+1 + γGt+1. Starting at G = 0 and updating G ← γG + Rt+1 at each backward step computes the exact discounted return for every time step in a single pass (O(T) total instead of O(T2)).
  3. Check the first-visit condition: Unless St appears in S0, ..., St−1 checks whether state St was already visited earlier in this same episode. If it was, we skip updating at step t and wait until the backward loop reaches the earliest occurrence of St.
  4. Record and average: At that first visit, append G to Returns(St) and set V(St) to the average of all recorded first-visit returns for that state. (Every-visit MC is identical except it omits step 3's check.)

5.2 Monte Carlo estimation of action values

Why vπ isn't enough without a model: In DP, knowing v* let us pick the best action via one-step lookahead arg maxa Σs', r p(s', r | s, a)[r + γ v*(s')]. Without p, state values alone cannot tell you which action leads to which next state. Therefore, MC control must estimate action values qπ(s, a) directly, so the policy can simply choose arg maxa Q(s, a).

The exploration complication: If π is deterministic, each state s only ever tries one action a = π(s), so returns for all other actions a' ≠ π(s) are never observed and Q(s, a') never improves. To guarantee every (s, a) pair is visited infinitely often, we need either:

  • Exploring Starts (ES): Every episode begins at a random state–action pair (S0, A0) where every pair has nonzero probability of being chosen as the start.
  • Stochastic policies: Keep π(a | s) > 0 for all s, a (Section 5.4), or separate the behavior policy from the target policy (Section 5.5).

5.3 Monte Carlo control

MC control follows the exact same Generalized Policy Iteration (GPI) pattern as Chapter 4, alternating policy evaluation and policy improvement on an episode-by-episode basis:

π0 E→ qπ0 I→ π1 E→ qπ1 I→ ··· I→ π* E→ q* Evaluation averages returns for Q(s, a); Improvement sets π(s) ← arg maxa Q(s, a)

To drop the unrealistic assumption of waiting for infinitely many episodes before each improvement step, Monte Carlo ES updates Q(St, At) and improves π(St) after every single episode. It cannot get stuck at a suboptimal policy (because if it did, Q would converge to qπ, forcing π to change).

Algorithm: Monte Carlo ES (Exploring Starts), for estimating π ≈ π*
Initialize π(s) ∈ 𝒜(s) and Q(s, a) ∈ ℝ arbitrarily; Returns(s, a) ← empty list

Loop forever (for each episode):
    Choose S0 ∈ 𝒮, A0 ∈ 𝒜(S0) randomly (all pairs have prob > 0)
    Generate episode from S0, A0 following π: S0, A0, R1, ..., ST−1, AT−1, RT
    G ← 0
    For each step t = T−1, T−2, ..., 0:
        G ← γ G + Rt+1
        Unless (St, At) appears in (S0, A0), ..., (St−1, At−1):
            Append G to Returns(St, At)
            Q(St, At) ← average(Returns(St, At))
            π(St) ← arg maxa Q(St, a)

5.4 Monte Carlo control without exploring starts

In real environments, you rarely get to teleport the agent to arbitrary starting (S0, A0) pairs. To guarantee exploration without Exploring Starts, there are two paradigms:

  • On-policy methods: Evaluate and improve the same policy that is used to generate decisions.
  • Off-policy methods: Evaluate and improve a target policy π using data generated by a different behavior policy b.

On-policy ϵ-soft & ϵ-greedy policies

An ϵ-soft policy keeps every action's probability at least ϵ / |𝒜(s)|. The classic example is an ϵ-greedy policy: all non-greedy actions get probability ϵ / |𝒜(s)|, and the greedy action gets 1 − ϵ + ϵ / |𝒜(s)|.

Why GPI still works: By the Policy Improvement Theorem, making π' ϵ-greedy with respect to qπ is guaranteed to improve any ϵ-soft policy π (because Σa π'(a | s) qπ(s, a) ≥ Σa π(a | s) qπ(s, a) = vπ(s)). Thus, it converges to the best possible policy within the class of ϵ-soft policies.

Algorithm: On-policy first-visit MC control (for ϵ-soft policies)
Initialize π to an arbitrary ϵ-soft policy; Q(s, a) ∈ ℝ; Returns(s, a) ← empty list

Loop forever (for each episode):
    Generate an episode following π: S0, A0, R1, ..., ST−1, AT−1, RT
    G ← 0
    For each step t = T−1, T−2, ..., 0:
        G ← γ G + Rt+1
        Unless (St, At) appears earlier in the episode:
            Append G to Returns(St, At)
            Q(St, At) ← average(Returns(St, At))
            A* ← arg maxa Q(St, a)
            For all a ∈ 𝒜(St):
                π(a | St) ← 1 − ϵ + ϵ/|𝒜(St)|   if a = A*
                              ϵ/|𝒜(St)|            if a ≠ A*

5.5 Off-policy prediction via importance sampling

The core problem: You want to learn the value vπ(s) of a target policy π (e.g., an optimal deterministic policy), but all your episodes were collected by a different, exploratory behavior policy b. To make this possible, b must satisfy the coverage assumption: every action π can take must have nonzero probability under b (π(a | s) > 0 &implies; b(a | s) > 0).

Derivation: Why environment dynamics cancel out in Importance Sampling

Given a trajectory At, St+1, At+1, ..., ST starting at St, its probability under policy π is ∏k=tT−1 π(Ak | Sk) p(Sk+1 | Sk, Ak). Taking the ratio of the trajectory's probability under π versus under b—called the importance-sampling ratio ρt:T−1—cancels out the unknown dynamics p completely:

ρt:T−1 ≐ ∏k=tT−1 [ π(Ak | Sk) p(Sk+1 | Sk, Ak) ] / ∏k=tT−1 [ b(Ak | Sk) p(Sk+1 | Sk, Ak) ] = ∏k=tT−1 π(Ak | Sk) / b(Ak | Sk) Eq. (5.3) · Depends ONLY on the two policies π and b—never on the unknown MDP dynamics p!

Multiplying an observed return Gt (generated under b) by ρt:T−1 reweights it to match the target distribution: 𝔼b[ρt:T−1 Gt | St = s] = vπ(s).

Ordinary vs. Weighted Importance Sampling

Let 𝓣(s) be the set of all time steps where state s was visited (across episodes, using continuous time indexing), and T(t) be the termination time after step t:

V(s) ≐ Σt∈𝓣(s) ρt:T(t)−1 Gt / |𝓣(s)| Eq. (5.5) · Ordinary Importance Sampling (simple average)

Unbiased (𝔼[V(s)] = vπ(s)), but can suffer from infinite variance because ρ ratios multiply across steps and can explode.

V(s) ≐ Σt∈𝓣(s) ρt:T(t)−1 Gt / Σt∈𝓣(s) ρt:T(t)−1 Eq. (5.6) · Weighted Importance Sampling (weighted average)

Biased initially (expectation starts at vb(s) on 1 sample, bias → 0 as n → ∞), but has finite, dramatically lower variance—strongly preferred in practice.

5.6 Incremental implementation

Just like Section 2.4's incremental average for bandits, we don't want to store all past returns and ratios Wk = ρt:T(t)−1. For weighted importance sampling over returns G1, G2, ..., Gn−1 with weights W1, ..., Wn−1, let Cn be the cumulative sum of weights so far:

Vn+1 ≐ Vn + (Wn / Cn) [ Gn − Vn ],    where   Cn ≐ Cn−1 + Wn   (C0 = 0) Eqs. (5.7)–(5.8) · O(1) memory and compute per step; ordinary IS simply uses Gn ← Wn Gn with weight 1/n

5.7 Off-policy Monte Carlo control

Now combine GPI with incremental weighted importance sampling to learn the optimal deterministic policy π(s) = arg maxa Q(s, a) while behaving according to any soft behavior policy b (e.g., ϵ-greedy).

The critical limitation of MC off-policy control: Working backward from t = T−1 to 0, the target policy is deterministic, so π(At | St) is either 1 (if At = π(St)) or 0 (if At ≠ π(St)). The moment the loop hits an exploratory action At ≠ π(St), the weight becomes W = 0, so we must Exit inner Loop! Thus, off-policy MC can only learn from the tails of episodes after the last non-greedy action—which slows learning and directly motivates Temporal-Difference learning in Chapter 6.

Algorithm: Off-policy MC control, for estimating π ≈ π*
Initialize Q(s, a) ∈ ℝ, C(s, a) ← 0, and π(s) ← arg maxa Q(s, a)

Loop forever (for each episode):
    b ← any soft policy
    Generate an episode following b: S0, A0, R1, ..., ST−1, AT−1, RT
    G ← 0,  W ← 1
    For each step t = T−1, T−2, ..., 0:
        G ← γ G + Rt+1
        C(St, At) ← C(St, At) + W
        Q(St, At) ← Q(St, At) + (W / C(St, At)) [ G − Q(St, At) ]
        π(St) ← arg maxa Q(St, a)
        If At ≠ π(St) then exit inner Loop
        W ← W · 1 / b(At | St)

5.8 Summary

Monte Carlo methods learn value functions and optimal policies directly from sample episodes without a dynamics model, offering four major advantages over Dynamic Programming—at the cost of needing complete episodes and dealing with higher variance.

Model-Free Learning

MC needs no transition probabilities p(s', r | s, a)—only simulated or real sample episodes, and can focus on small subsets of states.

No Bootstrapping

Each state's estimate is independent of other states' estimates, making MC less harmed by violations of the Markov property.

On- vs. Off-Policy

On-policy MC explores via ϵ-soft policies; off-policy MC uses weighted importance sampling, but only learns from greedy episode tails.
